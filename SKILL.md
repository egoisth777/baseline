# baseline

A drift-correction system. Over a long session the agent forgets standing rules (e.g. "route file read/write/search through subagents, don't do them inline"). baseline injects small, trusted **docs** into the model's context at chosen hook **events** on configurable **routes**. The classic use is the **recital**: every Nth user prompt the agent must open its reply with a fixed prefix line and restate the rules verbatim before continuing — which both *re-aligns* the agent and *exposes* drift.

Content and routing are kept separate: **docs** (`docs/*.md`) hold the verbatim injected text; **`config.json`** holds routing only (which doc fires at which event, how often, where). The dispatcher injects doc bodies as-is and bakes in no content. Static docs are the current default; deterministic placeholder replacement is a future opt-in design, not current runtime behavior.

## Architecture (what lives where)

| Piece | Path | Role |
|---|---|---|
| Dispatcher (Node fallback) | `src/baseline-recital.ts` → `scripts/baseline-recital.js` | TypeScript source for the Node dispatcher. Reads the event, loads `config.json`, selects routes, counts per route, injects due docs verbatim. Used when no native prebuilt is available or `--runtime node` is selected. |
| Shared dispatch contract | `contract/dispatch-contract.json` → `src/generated-contract.ts`, `src/native/contracts.zig` | Runtime-neutral protocol/layout values. Generated files are checked in and must not be hand-edited. |
| Zig/native hook runtime | `src/baseline-recital.zig`, `src/native/`, `bin/baseline-recital-*`, `bin/SHA256SUMS` | Thin composition root plus owned modules for resolution, input, config, counters, docs, emission, and diagnostics. Default hook hot path when a shipped prebuilt exists. |
| Install root | `BASELINE_HOME`, else the installed manager's own root, else `~/.baseline` | Holds regenerable artifacts only: deployed dispatcher (`hooks/`) + skill payload (`skills/`), plus `cfg` → your config folder. |
| Deployed dispatcher artifacts | `~/.baseline/hooks/baseline-recital.js`, native hook binary when active | Hook artifacts deployed by the Node manager. |
| Agent dispatcher link | `~/.claude/hooks/`, `~/.codex/hooks/`, `~/.pi/agent/hooks/`, `~/.omp/agent/hooks/`, `~/.config/opencode/hooks/` | Installed command path wired in hook config (or spawned by a shim); links to the install root. Native runtime wiring executes the native binary directly; Node wiring runs `baseline-recital.js`. |
| Extension shims | `~/.pi/agent/extensions/baseline-recital.ts`, `~/.omp/agent/extensions/baseline-recital.ts`, `~/.config/opencode/plugins/baseline/` | Generated, marker-tagged bridge for extension-host agents: forwards their extension events to the deployed dispatcher and injects its output. pi/oh-my-pi deliver `UserPromptSubmit` + `SessionStart`; opencode delivers all four events. Regenerated by install/update; carries no content or routing. |
| Config folder | `BASELINE_CFG`, else `<install root>/cfg` (`config.json` + `docs/` + `README.md`) | **Everything tunable**: routes in `config.json`, injected text in `docs/`. Pure config — no artifacts. `<install root>/cfg` symlinks here when `BASELINE_CFG` is set. |
| Agent config link | `~/.claude/cfg/baseline/`, `~/.codex/cfg/baseline/` | Links to `<install root>/cfg` (your config folder). Read live via symlink; a copy fallback needs install/update after edits. |
| Control-surface plugins | `.claude-plugin/plugin.json`, `.codex-plugin/plugin.json`, `skills/baseline/SKILL.md`, installed control-surface payloads | Plugin manifests and skill payloads make baseline discoverable. Installed payloads use the self-contained manager under the install root. Control surfaces carry no hooks. |
| Counter state | `<agent-config>/.baseline-counters.json` | Per-session, per-route firing state keyed `"<session>:<routeId>"`. Auto-pruned. Never edit by hand. |
| Wiring | `~/.claude/settings.json`, `~/.codex/hooks.json`; shim files (+ an `opencode.json` `plugin` entry) for pi/oh-my-pi/opencode | Our dispatcher command wired into exactly the events the config uses; a shim agent gets the shim exactly when the config has events it can deliver. `install`/`uninstall` manage it. |
| Manager | `src/manage.ts` → `scripts/manage.js` | install / update / doctor / verify / status / uninstall. Source runs deploy a self-contained copy under the install root. |
| Presets | `presets/default/`, `presets/minimal/` | Repo-shipped config payloads `install` seeds from. Plain `install` seeds `default`; `minimal` is the neutral opt-in floor. |
| Route templates | `assets/route-templates/*.md` | Doc+route authoring references. Never deployed or injected. |

**Key split:** routes/docs are *data* in your config folder (`BASELINE_CFG`, else `<install root>/cfg`) — pure config you can keep in a dotfiles repo (edit anytime; takes effect next firing). The dispatcher + skill payload are *mechanism/artifacts* under the install root `~/.baseline` (regenerated by `install`); config and artifacts never share a directory.

For canonical goal, architecture, and vocabulary docs, read `.arca/baseline-sp/goal/vision.md`, `.arca/baseline-sp/goal/architecture.md`, and `.arca/baseline-sp/goal/vocabulary.md`; `.arca/baseline-sp/goal/plain.md` is the compact decision summary.

## Requirements and runtime

Requires Claude Code, Codex, pi, oh-my-pi, or opencode, plus Node.js. Node runs the manager and remains the fallback/explicit dispatcher; when a shipped Zig/native prebuilt exists, plain install/update uses it as the default hook hot path. `--runtime node` forces Node.

## Trust boundary

Every `docs/*.md` is injected into model context, so treat docs as trusted configuration: inspect edits, keep them short, never paste untrusted text. The dispatcher caps `config.json`/each doc at 64 KiB, skips docs over 10,000 characters, caps the combined hook context at 10,000 characters, limits routes to 64, resolves each `doc` strictly inside the config folder after realpath checks, and fails open. If `status` reports a copy fallback for the config link, rerun install/update after editing the config folder.

Docs must be valid UTF-8; one malformed due doc makes the invocation emit nothing.
For redacted fail-open reason codes on stderr, set `BASELINE_DIAGNOSTICS=1`.
An explicit dispatcher `--agent-config` outranks inherited agent/home environment values.

## The two most common tasks

### Edit what is injected, or add a route — usually no reinstall

The config folder is `BASELINE_CFG` (else `<install root>/cfg`):

```json
{
  "version": 1,
  "routes": [
    { "id": "baseline", "event": "UserPromptSubmit", "freq": 5, "doc": "docs/baseline.md" }
  ]
}
```

- **Change injected text:** edit the doc the route points at (`docs/baseline.md`). The body is injected verbatim — the prefix/restate scaffolding lives inside the doc. Takes effect next firing.
- **Add a route:** add a `docs/<name>.md` and a `routes[]` entry. Follow `assets/route-templates/`. Then rerun `install`/`update` so hook wiring matches the events your routes use.
- **Change frequency/scope:** edit `freq` / `cwd` on the route.
- Editing only doc text needs no reinstall when `status` reports a symlink. Adding/removing an *event* requires install/update so wiring re-syncs.

### Manage the hook itself

Use the manager path named by the active control surface. Installed Claude and
Codex payloads point at `<install root>/scripts/manage.js`, so normal management
does not require the source checkout to remain present. When developing from a
source checkout, use that checkout's `scripts/manage.js` so install/update can
refresh the installed artifacts.

```bash
node "$BASELINE_MANAGER" status      # install root, config folder, dispatcher sync, routes, wiring
node "$BASELINE_MANAGER" install     # deploy dispatcher + seed preset + link agent + wire settings
node "$BASELINE_MANAGER" verify      # functional: confirm a route fires
node "$BASELINE_MANAGER" update      # redeploy + re-sync wiring from current config
node "$BASELINE_MANAGER" doctor      # validate config + wiring; --fix to repair
node "$BASELINE_MANAGER" uninstall   # unwire all events + remove agent links (keeps config folder)
```

Here `$BASELINE_MANAGER` means the exact installed or source path resolved above;
it is descriptive notation, not a required environment variable. Plain `install`
seeds the curated `default` preset; `--preset minimal` selects the neutral floor;
`--force` replaces an existing config folder (destructive). Source checkouts can
also use the platform installers (`./install.sh`, `.\install.ps1`). Commands are
idempotent and preserve co-resident hooks — hook-config edits are surgical.

For scripting, add `--json` to `status`, `route list`/`add`/`remove`, and `dispatch simulate` for versioned machine output (`{ "apiVersion": 1, "command", "data" }`; errors as `{ "apiVersion": 1, "error": { "code", "message" } }` with a nonzero exit). `dispatch simulate` is a side-effect-free dry run of what a `(event, cwd, source)` would inject. The CLI plus `--json` is the whole programmatic surface — no Node library export, no daemon.

## Workflow guidance for the agent using this skill

1. **Identify the intent.** Editing docs/routes → it's a `cfg/baseline/` edit. Installing/repairing/removing → it's a `manage.js` run. Adding or removing an *event* always needs install/update afterward (wiring re-sync).
2. **Resolve the baseline root before any command.** Do not assume the current working directory is this repo/plugin; users invoke skills from their own projects.
3. **For data edits:** read the relevant doc or `config.json`, make the change, keep docs short, keep `config.json` routing-only (never put injected text in it). Then run `node scripts/manage.js status` from the baseline root to show the live result.
4. **For mechanism changes** (how selection/counting/injection works): edit source first and do not hand-edit generated `scripts/*.js`. The default hook hot path is Zig/native when a shipped prebuilt exists; the Node dispatcher remains the fallback and explicit `--runtime node` path; the Rust CLI rewrite is a future architecture slice.
5. **For config-only changes:** do not run the user's project tests. End with `status` or `verify` from the baseline root. After any hook-config change, remind them: open `/hooks` once in the relevant agent, or restart, so hook config reloads.
